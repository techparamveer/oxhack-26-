How Sheep works

Your time has modes. In Focus, Rest and Play, the same Instagram and YouTube behave differently. Gemini plans your sessions and taps you on the shoulder when you doom-scroll. Sheep keeps a memory diary so it can say “yesterday you…”. Everything runs on the phone, and a Supabase backend quietly backs it up.

Wrapper: Instagram/YouTube's mobile website shown inside Sheep's own browser view, so Sheep can see the page path (never the content).
Fallback: hand-written text used when Gemini can't answer within 3 s. The demo never waits on Wi-Fi.

Tables · migrations/20261024171408_sheep_backend.sql

All five tables: RLS on, policies only to authenticated with (select auth.uid()) = user_id, anon gets nothing, user_id defaults to auth.uid(), rows cascade-delete with the user.

events select · insert
  • id bigint identity PK · user_id uuid → auth.users · client_id uuid · ts timestamptz · type text (1–40) · payload jsonb · created_at
  • unique (user_id, client_id) makes retries idempotent; index (user_id, ts desc)
  • Append-only: no update or delete grants. Mirror of events.jsonl, never DM or post content.
memory_files select · insert · update · delete
  • PK (user_id, path) · content text ≤ 200,000 chars · updated_at
  • One row per markdown memory file; latest write wins.
sessions select · insert · update
  • mode (idle/focus/rest/play) · title · planned_min · actual_min · done · total · xp · started_at · ended_at; unique (user_id, client_id)
  • ⚠️ Only Focus sessions create rows today (paired from session_start → session_end). Rest/Play only reach events.
daily_scores select · insert · update
  • PK (user_id, date) · score, focus, rest, play · updated_at
  • Written from Home, debounced 2 s (DailyScoreSync).
gemini_calls + consume_gemini_quota() select · insert · delete old
  • One row per proxied call. You can only delete your own rows older than a day, so you can't reset your own quota.
  • consume_gemini_quota(per_minute 30, per_day 500): security invoker (RLS still applies), per-user advisory lock, prunes rows older than 2 days. Callers can only lower the limits. Execute is granted to authenticated only.

Edge Function “gemini” · functions/gemini/handler.ts

1 · JWT

verify_jwt = true: only signed-in (anonymous) users get in.

2 · validate

POST only. 503 if the GEMINI_API_KEY secret is missing, 413 over 256 KB, 400 if contents is missing.

3 · Flash allowlist

gemini-flash-latest, flash-lite-latest, 2.5-flash(-lite), 2.0-flash(-lite), 3-flash-preview. Anything else → 400.

4 · quota

Calls rpc/consume_gemini_quota with the caller's JWT (3 s). RPC failure → 503, over the limit → 429.

5 · forward

Sends only contents, systemInstruction and generationConfig upstream with the secret key. 15 s timeout → 504; network error → 502; Gemini's status passes through.

Swift side · Services/Supabase/

Auth

Anonymous sign-up, token refresh, session kept in UserDefaults. A revoked token gets a new anonymous user; failed sign-ups back off 60 s.

SupabaseAuth.swift
Hooks

EventLog.append → events (+ a sessions row on session_end) · MemoryStore.write/delete → memory_files · Home score → daily_scores.

SupabaseSync.swift
Retry queue

A JSON file on disk. Coalesces by key, sends up to 50 per batch, backs off 2 s → 10 min. Network/auth failures are never dropped; bad rows are dropped after 12 tries; capped at 1,000 ops.

SyncQueue.swift
Offline memory

After a connectivity error, every Supabase call fails instantly for 15 s, so nothing waits on the radio.

The memory loop

How “yesterday you… lock in” happens

Yesterday's events are written into timeline/daily/<yesterday>.md at session end or on the first open of a new day. MemoryContext.build always puts a “Yesterday (Friday …)” block near the top of {{MEMORY}}, and the Persona tells Gemini to bring it up. Offline, OfflineBrief.recapSentence builds the same sentence straight from the raw events. Tap a step.

7 · status vs the mvp plan

Where we are

Docs vs code

  • MVP_PLAN says the backend is “out of scope” and Gemini is called directly. In the code, Supabase is the default path and the direct key is a dev fallback. BUILD_PROMPT and CLAUDE.md were updated; MVP_PLAN wasn't.
  • BUILD_PROMPT gives Play accent #E07A2E and a “warm off-white” background. Code and Paper use #E8A93B and fog #ECEDEB.
  • BUILD_PROMPT's Theme sample uses weights 600/700. The real scale is 400–900 (no thin type).
  • MVP_PLAN treats feed and Reels differently in Rest (“lenient” vs “monitored”). Code uses one Rest threshold for every section.
  • Memory budget: docs say ~1.5k tokens, code caps at 6,000 characters (about the same).
  • Moving from the feed to Reels or Shorts does not count as “returned” after a nudge. Only leaving, opening DMs or tapping a leaving button does.
  • BUILD_PROMPT step 6 asks for a brief refresh button. There isn't one; the brief refreshes on rollover, seed and reset.
